# Installation guide - Unified Return Management

## 1. Install

1. Copy the `unified_product_return_policy` folder into an addons path of your Odoo 20 server.
2. Restart Odoo, enable the developer mode, then *Apps → Update Apps List*.
3. Search for *Unified Return Management* and click *Activate*.

Dependencies installed automatically: `sale_stock` (Sales, Inventory), `pos_stock` and `pos_hr`
(Point of Sale with employees). *Log in with Employees* does not have to be enabled on your points of
sale.

Tested on Odoo 20 Community and Odoo 20 Enterprise. Install on a test database
first and check your own flows before using it in production.

## 2. Enable the policy per company

*Inventory → Settings → Unified Return Policy*:

* **Default Return Period (Days)**: used when neither the product nor its category has a period;
  must be greater than 0.
* **Timezone**: the deadline ends at the end of the local day in this time zone.
* **Return Period Calculation Based On**:
  * *Actual Validation Date*: server time of the delivery validation, never changes;
  * *Effective Date*: follows later corrections of the delivery date.

Each company has its own settings. Nothing changes for a company until the policy is enabled, and
sales made before that keep the standard Odoo behaviour.

The *Allow Spontaneous Returns* setting of Inventory (portal returns and their period) stays in use:
the portal period is capped by the product's return policy.

## 3. Set periods on categories and products

*Return Policy* section of a product category form, or of the *Sales* tab of a product:

* **Use Custom Return Period** and **Return Period (Days)**.
* Priority: product, then its direct category, then the company default.
* **0 days** means non-returnable: no return in any channel without an approved exception.
* Values are set per company.

## 4. Point of Sale approvals

*Point of Sale → Configuration → Return Approval PINs* (POS Administrators): issue an approval PIN to
a POS Manager employee. The PIN is generated by the server (8 digits), shown once to the
administrator who issued it, and handed to the employee in person. Issuing a new PIN revokes the
previous one; each issue is logged on the employee. A POS Administrator can also approve with an
Odoo login and password (and the TOTP code when two-factor authentication is enabled).

## 5. Access rights

No new group. The module uses the standard groups:

| Who | Can |
|---|---|
| Sales user (*Own Documents Only*) | request return exceptions for their own or unassigned sales orders, and see those |
| Sales user (*All Documents*) | the same for every sales order |
| Sales Administrator | approve or reject Sales return exceptions |
| Inventory User | create and validate returns; see the approvals of their company (they execute them) |
| POS User | request POS refunds; see POS approvals |
| POS Administrator | approve POS exceptions; issue approval PINs |
| Portal user | request returns of their own delivered orders |

An approval never grants stock rights: the return is validated by an Inventory User.

## 6. Uninstall

Uninstalling removes the module's data (policies, requests, approvals and their history). Export
what you need first.
